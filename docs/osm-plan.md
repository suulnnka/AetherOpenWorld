# OSM 真实地图 → 游戏地图 转换方案(三环内 · 1:4)

目标:以 OpenStreetMap 真实数据为底,按 **1:4 比例(1 世界单位 = 4 米)** 重绘北京三环内城区,
产出可直接烘焙/游玩的地图 JSON。流程:**分片抓取 → 逐片转换 → 合并成图 → 服务端烘焙**。

## 1. 数据源与抓取

- **数据源**:Overpass API(OSM 官方查询服务),镜像优先级:
  `maps.mail.ru`(实测可用)→ `overpass-api.de` → `kumi.systems` → `private.coffee`,逐个降级。
- **范围(三环内 + 护城河缓冲)**:经度 116.288 ~ 116.470,纬度 39.845 ~ 39.978。
  实测:三环 E-W ≈ 13.3km、N-S ≈ 11.9km → 1:4 后城市约 **3330 × 2980 单位**,世界尺寸 3600。
- **分片**:8 列 × 7 行 = **56 片**,每片约 2.0km × 1.9km("一块一块的转");
  每片一个 Overpass 查询,原始 JSON 缓存到 `tools/osm-cache/tile_{x}_{y}.json`,
  已存在的片跳过 → **断点续抓**,失败片自动重试(最多 3 次,间隔退避)。
- **查询内容**:`building` / `highway`(全部等级)/ `natural=water` / `leisure=park|garden` /
  `landuse=grass|forest|meadow`(含 relation 多边形),`out geom` 直接带坐标。

## 2. 坐标变换

```
原点 lon0=116.379, lat0=39.9115(三环 bbox 中心附近)
east_m  = (lon - lon0) × 85300     (米/度,cos39.9°)
north_m = (lat - lat0) × 110800
世界坐标:x = east_m / 4, z = -north_m / 4     (北 = -Z,与现有城市一致)
```

## 3. 要素映射表(OSM → 游戏元素)

| OSM | 游戏数据 | 说明 |
|---|---|---|
| highway=motorway/trunk/primary | `roads[]` c=major | 路宽 max(实际/4, 9u),沥青深色+中线虚线 |
| highway=secondary/tertiary | `roads[]` c=mid | max(实际/4, 6u) |
| highway=residential/unclassified/living_street/pedestrian | `roads[]` c=minor | max(实际/4, 4u);footway/path/steps 丢弃 |
| building(含 levels/height 标签) | 元素 `bldg` | **真实多边形挤出棱柱**;层数缺省按 footprint 面积分级估算 |
| natural=water / riverbank | 元素 `water`(多边形) | 平铺水面,保留后海/北海/护城河真实形状 |
| leisure=park|garden、landuse 绿地 | 元素 `green`(多边形) | 草坪面 + 内部散树(点内判定) |
| 命名 POI / 固定坐标表 | 31 个风格化地标 | 见 §5 |

## 4. 减面与聚簇(控制烘焙体积)

三环内建筑 ways 量级 10 万+,必须简化(目标 ≤ 2 万个棱柱、≤ 130 万顶点):

1. **Douglas-Peucker 简化**轮廓:建筑容差 0.8u、道路 1.2u、水面/绿地 2u;建筑轮廓 ≤ 12 顶点。
2. **二环内**(切比雪夫距 < 1000u):面积 ≥ 350m²(≈22u²)的建筑保留真实多边形;
   更小的"胡同房"按 30u 网格聚簇 → 每格 ≤ 3 个合并矩形,簇 < 100m² 丢弃。
3. **二环~三环**:阈值提高到 600m²,小房同样聚簇,簇 < 200m² 丢弃。
4. 退化/自交多边形(三角化失败)→ 回退为最小外接矩形(OBB)。
5. 道路逐段画为**三角带四边形**(每段 4 顶点,不是盒子),同类道路以 0.01 级高差 +
   段内微抖动消除交叉口 Z-fighting。

## 5. 风格化地标(31 库内 · 三环范围内 16 座)

经纬度定位(名称匹配 OSM 命名要素时用其质心覆盖):

故宫、天安门、天安门广场、正阳门、永定门、景山、鼓楼、钟楼、雍和宫、妙应寺白塔、
北海白塔、天坛·祈年殿、国家大剧院、央视大楼、中国尊、国贸中心、北京站

每个地标落位后,**半径内(地标 radius×0.9,≥60u)的 OSM 建筑/支路清除**,避免穿模。

## 6. 风格化补偿(说明)

严格 1:4 下 20m 建筑 = 5u 宽、6 层楼 = 4.5u 高,与 2.4u 高的角色、4.6u 长的车比例失衡。
为保持低模观赏性,**水平位置/形状严格 1:4,竖向高度 ×1.6 夸张**,道路宽度设下限;
角色/车辆/行人尺寸与原版一致。补偿系数集中在工具一处配置,可调。

## 7. 工具与产物

- `tools/osm-import.mjs`:`--fetch`(逐片抓取+缓存)/ `--convert`(逐片转换+合并)/ `--all`
- 几何工具库 `public/js/poly.js`(DP 简化、耳切三角化、点内判定,游戏渲染端共用)
- 渲染端 `city.js` 新增:`bldg`(多边形棱柱)、`green`/`water`(多边形)、`roads[]` 折线路网;
  地图 `settings.groundStyle='terrain'` 时不画整体沥青底板,改画真实路网
- 产物:`data/maps/osm_ring3.json`「北京·三环内(OSM 1:4)」→ 烘焙 → 游戏/编辑器直接打开
- 车流/人群:从 `roads[]` 的 major/mid 折线生成 PolylinePath(往复行驶),
  替代环路矩形路径;小地图同步绘制真实路网


## 8. 执行结果(2026-10-28 实测)

- 抓取:56 片全部完成(镜像自动降级 + 本地 3000 端口中转代理,单片 15~90s,断点续抓生效)
- 转换:34,941 建筑 → 16,275 棱柱(独立多边形 10,362 + 聚簇 5,913,丢弃 5,592);
  9,135 条道路(出界要素已过滤)、64 水面、322 绿地、17 地标;地图 JSON 2.9MB
- 烘焙:18.9MB / 10.5s / 107 万顶点 / 16,314 碰撞盒;浏览器整帧 1.47ms
- 已知取舍:竖向 ×1.6 夸张、道路宽度设下限、小建筑聚簇合并(方案 §4/§6)
